## 这是什么

Miru 基于开源项目 [Kazumi](https://github.com/Predidit/Kazumi) 修改而来。

原项目是一个通用的番剧采集与在线观看程序。Miru 在它的基础上做了两件事：**把内容面向国漫收敛**，以及**把界面整个重做一遍**。

**只提供 Android 版本。** 本仓库已移除 iOS、Web、Windows、Linux、macOS 等其他平台的源码与构建配置，仅保留 Android 相关的内容，不再提供其他平台的构建。

## 功能全景

> 下面是 Miru 相对原版 Kazumi 改动与新增的全部能力，按域分组。

### 开屏与视觉

- **液态玻璃开屏**：巨大的玻璃穹顶坐在屏幕底缘，上滑推至屏中，一路真实折射身后的云海/星空（放大 + 边缘剪切 + RGB 色散），落定后贴纸从玻璃里升起结成羽流、标题对焦扫入。白天（Sky）循环云海 + 旅行贴纸，深夜（Astro）星空 + 地平光晕；**昼夜三重判定**（应用内深色 / 系统深色 / 北京时间 23:00–06:00 深夜窗口）任一命中即切夜版。
- **更新后重放开屏**（v1.6.7 新）：每次应用更新后的首次进入，都会完整播放一遍开屏动效；另有「每次启动显示开屏」开关可选。深夜冷启动不闪白（原生层同源起帧 + 渐变），旋转/主题热切换不重置。
- **悬浮液态玻璃导航 Dock**：主界面底部是一块悬浮圆角玻璃板，内容从其下滚过时被真实折射 + **全通道高斯磨砂 + 逐像素磨砂颗粒**（v1.6.7 重写：R/G/B 三通道全部化开、沙磨颗粒质感、乳白底色，任何封面滚过都只剩色彩呼吸）；页签滑块是**弹簧模拟的液态小球**，运动中按实时速度拉伸压扁、过冲回弹，切页签带触觉反馈，双击当前页签回顶。
- **统一玻璃材质体系**：顶栏、弹层、卡片、FAB 全套毛玻璃/液态玻璃组件，亮度层级统一（Dock > 弹层 > 卡片）；不支持着色器的设备自动降级为同观感毛玻璃，绝不黑块。
- **排印与主题**：全局思源宋体（Noto Serif SC）衬线排印；8 款精选免费商用字体（霞鹜文楷/思源黑体/站酷快乐体/龙藏体/马善政体等）按需下载、即时生效；中性化配色参考 iOS 表面色阶，强调色只出现在交互元素上。
- **骨架屏与空态**：推荐页/搜索页/详情页全套骨架屏，下拉刷新，加载/空/错误三态齐全可重试。

### 播放器

- **mpv 内核**（media_kit）：硬件解码、倍速、自定义字幕样式（白字软投影，非默认粉色巨字）、画面比例裁切、截图分享。
- **Anime4K 超分辨率**：内置 Anime4K CNN 着色器链一键开启，低分辨率老番实时拉质。
- **交互细节**：双击屏幕左右侧 ±10 秒快进退；进度条按拇指位置精确换算；选集网格当前集高亮 + 已看角标；点控制栏重置自动隐藏计时；锁定列带衬底、横屏避让挖孔；定时关闭、PIP 画中画。
- **v1.6.7 声画同步三重根因修复**：① 隐藏嗅探 WebView 的漏音通道全部封死（muted/volume setter 劫持 + `<audio>` 覆盖 + 完整 AudioContext 桩）——“有声音却在加载中”的假象消除；② 起播遮罩改以 mpv 真实首帧信号为准（videoParams 宽高就绪），“解析完成→首帧渲染”的黑窗口不再暴露给用户；③ 起播缓冲恢复门槛回旧上游默认（1s），音频先出、画面后到的起点差被消除。
- **换集秒切**：播放器实例与纹理常驻复用（v1.6.7 修复换集时误卸载 Video 导致的纹理重建竞态），解析与停流并行；播放稳定后自动预解析下一集。
- **起播分级缓冲**：起播阶段小缓冲快出首帧，稳定后自动拉高到 120 秒；分片级自动重试重连；错误提示延迟复检（只有真卡死才提醒）。
- **加载反馈真实化**：加载层文案随真实阶段切换（解析中→已解析、缓冲中）并实时显示已耗时秒数；解析失败态直接给重试/换线路按钮。
- **线路健康探测**：进播放页后台摸底各线路可用性与延迟（不打扰源站、10 分钟持久化），换线路菜单显示 ⚡+毫秒徽标，无播放历史时自动选健康线路。
- **同步观看**：SyncPlay 房间与好友同步播放；也支持调用外部播放器。

### 解析链路（五级漏斗 + 对冲竞速）

- **五级漏斗**：本地解析缓存（带签名感知 TTL，按直链真实剩余寿命缓存）→ 本地快速静态解析（0.3~1s，出口 IP 与播放器一致，从根上消除防盗链拒播）→ 云端解析层（内置 Cloudflare Worker 端点，多端点竞速）→ 本地 WebView 嗅探（headless、防外放、广告/统计域拦截省流量）。
- **对冲竞速**：快解/云端/嗅探分层梯队同时推进（0ms/600ms/1500ms），任何一路先拿到可用直链立即开播，其余让路；**超时 5~120 秒可调且真实生效**（v1.6.7：慢 JS 站不再被内部 12 秒硬上限砍掉）。
- **多候选并发验证**：本地快解的多候选直链 3 路并发探测取最快可用者；探测三态判定（仅明确 4xx 判死，慢/抖动一律放行）。
- **防盗链头全链路保持**：解析层确认的 Referer/Cookie 持久化进缓存、随直链传给播放器（v1.6.7：解析层确认头优先于插件硬编码，「探测可达但播放 403」消除）；Cookie 全链路单头归一。
- **负缓存分级 + 误伤半径控制**（v1.6.7）：host 级失败记忆 10 分钟→3 分钟，且换线路/换集首次查询放行——一次误分类不再把整站打入冷宫。

### 本地媒体代理（边播边缓存）

- MP4 Range 代理 + HLS 清单改写分片缓存；解析出直链后后台预取开头数据，点播放首帧从磁盘秒出。
- 滑窗预取器始终领先播放头 4 个分片，快进回看不卡顿；计量网络自动跳过预取不偷跑流量。
- **独立音轨组同通道代理**（v1.6.7）：HLS master 声明的 EXT-X-MEDIA 音频 rendition 不再被丢弃或直连——视频/音频两路都走本地代理，消除「画面冻结声音走」的双通道速度差。
- 直连兑底：代理万一打开失败，mpv 自动用原始直链原地重开，用户无感知。

### 下载

- 与播放共用五级解析漏斗，下载不再逐任务硬嗅探；断点续传带 m3u8 清单指纹（换线路不混源损坏）。
- 后台下载服务 + 通知栏进度；同集号换线路覆盖重下（v1.6.7 修复进度缓存影子打穿）；暂停/恢复/优先级/并发可调度。

### 数据与同步

- **GitHub 云同步**：应用内 OAuth 登录面板（不跳外部浏览器），收藏/观看历史/追番变更日志三方合并，多设备增量同步；**远端损坏红线守卫**（v1.6.7：快照缺失+日志存在的异常状态不再清空本地收藏，自动推本地全量修复远端）。
- **WebDAV 同步**：同套合并引擎与提交器（v1.6.7：rename 失败窗口的直传兑底，远端文件不再丢失）。
- **Bangumi 收藏同步**：与 bgm.tv 双向同步在看/想看/看过状态。
- 推荐页/时间表本地持久化：加载一次后启动直读本地不联网。

### 规则系统

- 内置国漫优先规则集；规则商店 + 社区规则目录接入（Kazumi 生态规则地址直接粘入可用）。
- 规则编辑器：XPath/API 双模式、字段级校验、未保存离开拦截、测试页探针。
- 插件健康度追踪（连续失败的源自动排后）、会话级 Cookie 管理、Cloudflare 验证 WebView 自动处理。
- 首启自动装规则，免逐条点安装。

### 网络与运维

- Bangumi 官方 API 走社区公共反代（无需密钥），官方/镜像多路竞速回退；图片代理失败自动回退原图直连。
- 远程公告系统：仓库内 `announcement.json` 驱动的玻璃弹窗（封面图/按钮/字体可配，定时生效/版本区间/频控，改一个字段即可上下线无需发版）。
- 新版本提醒：镜像+直连并发探测下载，应用内更新弹窗、忽略此版本。
- 系统代理识别、计量网络感知（移动数据自动切低内存模式）、匿名活跃统计（仅一个随机 ID，用于云端解析配额分配）。

## 改了什么

### 内容：只推国漫

- **推荐页与时间表按产地标签过滤**，只出国产动画，不再混入日番。想切回去只需改 `ApiEndpoints.bangumiRegionTag` 一个常量。
- **首页顶部固定横幅**，用内置的 16:9 官方主视觉图，不再拿竖版海报硬裁成横图。
- **置顶片单**：指定的国漫排在推荐流最前，顺序可在 `lib/request/config/featured_bangumi.dart` 里调整。

### 网络：解决国内直连不通

Bangumi 官方 API 在中国大陆无法直连。原项目通过自建 mirror 解决，但那个 mirror 需要签名密钥，**自建包拿不到密钥，会导致搜索、评论、热门、时间表全部失效**。

Miru 改用无需鉴权的社区公共反代：

| 官方域名 | 反代 |
| --- | --- |
| `api.bgm.tv` | `bgmapi.anibt.net` |
| `next.bgm.tv` | `next.bangumi.lol` |

> ⚠️ 这两个反代是社区个人维护的公共服务，可能限流或停服。真出问题时，改 `lib/request/config/api_endpoints.dart` 里的域名常量即可切换。

### 界面：重做

- **衬线排印**：全局使用思源宋体（Noto Serif SC），中英文统一。
- **液态玻璃材质**：导航条、顶栏、弹窗、选中态。页签滑块由弹簧模拟驱动，并按实时速度做拉伸压扁。
- **中性化配色**：参考 iOS 的表面色阶体系，强调色只出现在交互元素上，不铺满背景。
- **首页版式**：大横幅轮播 + 竖版海报网格。

### 体验

- **首启自动装规则**：不必再逐条点「安装」。
- **推荐页与时间表本地持久化**：加载一次后，之后启动直接读本地，不再联网。
- **播放源平铺**：选播放源时直接列出所有搜到的结果，不用先选来源再选结果。

## 安装

1. 到 [Releases](https://github.com/DisenthrallClaude/Miru/releases/latest) 下载 APK（直链：[Miru-1.6.7-android-arm64-release.apk](https://github.com/DisenthrallClaude/Miru/releases/download/v1.6.7/Miru-1.6.7-android-arm64-release.apk)），每个版本附 `.sha1` 校验文件
2. 安装（首次需允许「安装未知来源应用」）
3. 首启跟着引导走完，规则会自动装好

**要求 Android 10 及以上，设备为 arm64 架构（2018 年后的主流机型基本都是）。** APK 只包含 `arm64-v8a` 单架构，体积更小；模拟器 / x86 平板不在支持范围内。

- **更新后重放开屏（新功能）**：每次应用更新后的首次进入，完整播放一遍高级开屏动效。
- **高危数据修复 3 项**：同集号换线路覆盖重下被进度缓存影子打穿（新任务静默流产）；远端收藏快照损坏时不再整盒清空本地收藏并扩散全设备（红线守卫 + 提交器直传兑底）；下载进度回调异常逃逸防护。

### 1.6.6

- **底部导航真磨砂（本次主修）**：v1.6.5 的玻璃模糊只作用在绿通道——红蓝通道仍是清晰采样，动漫封面的轮廓线透过红蓝通道依然纤毫毕现，这就是「隔着玻璃还能看清动漫」的根因。现在改为双 pass 磨砂架构（参考 liquid_glass_easy 组件的组合方式）：底层先做引擎级全通道真实高斯（R/G/B 全部化开成色彩呼吸），上层折射着色器叠在磨砂基底上做弯折、rim 色散与顶部高光——既是液态玻璃，也是真正的磨砂质感；磨砂强度与乳白底色同步上调（28σ / 亮 0.45 / 暗 0.55），消除边缘漏缝。

**播放提速与规则修复（实测数据驱动）：**

- **新增本地快速解析通道**：播放页 HTML 直接在手机本地静态提取（0.3~1 秒，云端解析要 1.5~3.5 秒），且出口 IP 与播放器完全一致——从根上消除「云端拿到的直链被源站防盗链拒掉」的问题。解析漏斗升级为五级：本地缓存 → 本地快速解析 → 云端解析 → WebView 嗅探，任何一级失败自动降级。
- **修复云端解析对一批 MacCMS 站全挂的根因**：player_aaaa 变量里嵌套的 `vod_data` 对象会让旧正则提前截断、JSON 解析必然失败（淘片等站全部中招）。云端与本地解析都已改为括号配平提取，并支持苹果CMS 官方 encrypt=1（escape）/encrypt=2（base64+escape）加密解码。
- **mpv 起播码率修复**：mpv 默认 HLS 选最高码率流，弱网下首帧要等好几秒——这正是「几秒拿到直链却迟迟不出画面」的头号元凶。现改为取首个流（站点推荐清晰度）起播，明显加快出画；连接超时从 60 秒降到 10 秒，坏链快速失败快速换源。
- **修复 16:9 轮播海报点了加载不出来**：详情数据接口原走 next.bgm.tv（国内时好时坏），其配对的镜像 next.bangumi.lol 对非浏览器请求一律 403——竞速形同虚设。已切到 api.bgm.tv + 镜像双路竞速（镜像实测稳定），首页轮播、详情页、置顶清单全部受益。
- **防盗链请求头不再丢失**：解析层确认的源站 Referer 现在会随直链一起传给播放器（之前会丢，是「探测可达但播放 403」的经典原因）；HLS 探测同时校验响应内容确为 m3u8 索引（防错误页 200 误判）。
- **全规则实测**：13 条规则逐条跑通「搜索→详情→选集→解析→探测」全链路并测速，静态可解析的源全部进入秒级解析通道；JS 动态渲染/第三方解析器型源自动走 WebView 兜底。已知站况：dalvdm 域名已失效（等站方恢复）；AGE 有 Cloudflare 盾（由 WebView 自动处理）。

## 已知问题

**本项目仍有大量 bug 和待优化之处，不是成熟产品。** 已知的有：

- **弹幕功能失效**。弹幕依赖弹弹play 的签名密钥，自建包拿不到（上游 Kazumi 的凭据随 CI 闭源注入）。修复路线已梳理（申请自有凭据 / 本地弹幕文件导入），见 `docs/plans/04-danmaku-fix.md`。相关的失败提示已经移除，不再反复打扰。
- **部分番剧播放失败**。播放依赖第三方站点的采集规则，站点改版规则就会失效，表现为「播放器内部错误」。可以换个数据源试试。1.2.0 已对齐上游 Kazumi 的最新播放修复并加固了解析链路，命中率比 1.1.0 高，但站点侧的失效仍无法根治。
- 只在少数机型上测过，兼容性未知。
- 界面在横屏与平板上的适配不完整。

## 常见问题与解决方法

Miru 继承自 [Kazumi](https://github.com/Predidit/Kazumi)，很多麻烦其实来自「规则 / 播放源」这套第三方生态，而不是 App 本身。站点一改版、规则一失效，就会出现「某部番放不了」。遇到时按下面的顺序排查：

### 播放失败 / 提示「播放器内部错误」

1. **多刷新几遍。** 规则和搜索结果大多是动态拉取的，网络抖动或源临时抽风时，多刷几次往往就能恢复。
2. **切换播放源 / 线路。** 同一部番通常有多个播放源（选集页的「播放线路」），这个源打不开就换下一个，命中率会高很多。
3. **更新或重建规则。** 在「规则」页找到对应站点，删除后重新添加，让 App 重新拉取该站点的最新规则。
4. **自己去找规则配置。** 社区维护的规则合集（Kazumi 生态的规则地址）有很多，在 App 里「添加规则」粘贴规则地址即可接入更多播放源。规则装得越多、可用性越高，一个失效就换另一个。

### 搜索 / 推荐 / 时间表打不开

列表数据走 Bangumi 官方 API 的社区反代（见上文「网络」一节）。反代是个人维护的公共资源，可能限流或停服：

- 先多刷新几遍；
- 若长期打不开，去 `lib/request/config/api_endpoints.dart` 换一个反代域名即可。

### 弹幕不显示

弹幕依赖[弹弹play](https://www.dandanplay.com/)的签名密钥，自建包拿不到密钥，因此弹幕功能不可用（详见上文「已知问题」）。
